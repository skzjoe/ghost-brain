# Ghost workspace guidance

Read `memory/reference/PLAYBOOK.md` for operating rules and `memory/reference/SECOND-BRAIN.md` for capture/recall. Load project context only when relevant and verify important claims at their source.

- OpenClaw owns runtime, tools, permissions, orchestration and scheduling. Use its approved native controls.
- Use native Skill Workshop when available, under its approval policy; do not start legacy automatic skill pipelines.
- Obsidian is canonical when configured. Read the vault schema and existing workspace routing before any knowledge write. Local notes are staging and indexes/status views are derived.
- If no vault is configured, use an agreed local memory convention; do not invent a vault path.
- Preserve existing user data and unrelated work. Keep private context out of public artifacts.
- Complete requests through verified delivery or a concrete blocker. Running is not done.

This is generic starter guidance, not a replacement for your existing security or project rules.
