# Negotiation Prep

Prepare negotiation artifacts that are operational, compact, and ready to use before real conversations.

## Core operating rules

- Optimize for **decision quality**, not motivational advice.
- Focus on **BATNA, real objective, issue mapping, trade design, and clear commitment**.
- Distinguish between **position** and **interest**.
- Push toward **multi-issue negotiation**, not single-issue haggling.
- If the user wants a reusable document, create it in Markdown.
- Prefer concise one-page formats unless the user explicitly asks for a long memo.
- When given a real case, create a **first-pass filled draft** instead of defaulting to a blank template.
- Mark uncertainty clearly as **Confirmed**, **Assumption**, or **To confirm**.

## Main workflow

### 1. Identify the negotiation type

Choose the closest mode:

1. **General negotiation prep**
2. **ERP / client deal prep**
3. **Vendor / subcontractor prep**
4. **Hiring / compensation prep**
5. **Cheat sheet / framework only**
6. **Live-case filled draft**

If the user does not specify, start with the general template and then specialize.

If the user provides a real situation, switch to **Live-case filled draft**.

### 2. Clarify the prep objective

Identify whether the user needs:
- a reusable blank template
- a filled draft for a real negotiation
- a quick checklist
- a cheat sheet of principles
- a domain-specific prep sheet

### 3. Use the right reference file

Read only the references relevant to the request:

- `references/general-template.md` for universal negotiation prep
- `references/erp-client-deal.md` for ERP/client negotiations
- `references/vendor-subcontractor.md` for vendor/subcontractor negotiations
- `references/hiring-compensation.md` for hiring/compensation negotiations
- `references/cheat-sheet.md` for concise negotiation principles
- `references/live-case-mode.md` for first-pass filled drafts
- `references/inference-rules.md` for safe inference behavior
- `references/opening-approaches.md` for practical opening moves

### 4. Build around the same core structure

When producing a prep sheet, cover these sections unless the user asks for a lighter version:

- deal context
- real objective
- BATNA / alternatives
- likely interests of the other side
- negotiable issues map
- concession plan
- package/offer design
- opening strategy
- close / commitment checklist

For live-case drafts, also include:

- **Open questions to confirm**
- **Recommended opening approach**

### 5. Keep it practical

A good output should help the user answer:
- What do I really want?
- What is my next-best alternative?
- What can I trade?
- What likely matters to the other side?
- What packages can I offer?
- What is my walk-away point?

### 6. Handle partial information intelligently

If the case information is incomplete but usable:
- fill the draft with what is known
- label uncertain fields clearly
- avoid pretending assumptions are facts
- ask only for the minimum follow-up needed

## Output expectations

Prefer one of these formats:

- **Markdown template** for reuse
- **Filled negotiation prep sheet** for a live case
- **Cheat sheet** for quick review before a call/meeting

## Practical quality bar

Good outputs:
- help make better decisions under pressure
- create room for package deals
- avoid vague business-speak
- separate must-have from nice-to-have
- end with a clear next-step or decision test
- remain useful even when some information is still missing
